# 🚌 踏查文案小幫手

把每週二的「戶外踏查」和「週會」整理成家長 LINE 訊息、FB/IG 貼文、問卷題目和教學紀錄。

## 一個共用帳號，三種工作

全校老師共用**同一組帳號密碼**（帳號只要打 `teacher`，不用 Email）。登入後選「今天要做什麼工作」，系統只顯示需要的功能；做完按右上角「🔄 切換工作」。

| 工作 | 看得到的分頁 |
|---|---|
| 🚌 踏查、週會、發送 | 全部（包括 ⚙️ 設定、📊 全校問卷檢查） |
| 📝 批改小小孩問卷 | 📝 答案批改、📋 本週名單 |
| 📝 批改大孩子問卷 | 📝 答案批改、📋 本週名單 |

AI 鑰匙只要在「⚙️ 設定」貼一次，三種工作都會用它。

⚠️ **不同電腦要登入同一個帳號，一定要先設定 Firebase**（見下面「第一次設定」第 2 步）。本機試用模式的帳號只存在一台電腦的瀏覽器裡。

## 系統做了什麼

| 頁面 | 功能 |
|---|---|
| 🚌 踏查 | 行程表／學習單 → 挑照片（自動縮小）→ AI 看照片，老師核對 → 問卷連結 → 產生文案 → 發布前檢查清單 → 一鍵複製 |
| ⛪ 週會 | 貼上逐字稿 → AI 照範例格式整理成 300 字內的家長信（🎙️ 錄音轉逐字稿預設藏起來，可在設定打開；錄音不存檔） |
| 📤 本週發送 | 照 LINE 的順序排好：週會 → 踏查 → 照片；顯示「每週二 17:00」發送倒數；**檢查清單勾完 → 按「✅ 確認」→ 郵差時間到自動發到 LINE 官方帳號、FB 粉專、IG**（IG／FB 可以附 1～10 張照片，自動裁成 IG 能收的比例；可取消、失敗可重送）；也可以一鍵複製 |
| 📍 踏查地點 | 地點庫（室內／室外、交通、季節、去過的日期、打名字就知道什麼時候去過）；可匯入整理好的 Excel；自動排 10 週（第 1、5、9 週固定總圖，依學季季節挑地點），每週有 ☀️ 晴天和 ☔ 雨天（一定是室內）兩個地點；每週二 13:30 出發、16:00 回青埔 |
| 📊 問卷檢查 | 上傳 Google 表單回覆＋學生名單（可上傳 Excel、可記住）→ 找出未交、遲交、重複交、名字打錯；用 AI 批改簡答題（只送代號，不送名字） |
| 📋 本週名單 | 三位老師各自按「存進本週名單」後，自動合併：未填問卷、大孩子老師出題全對、大孩子自出題全對、小小孩全對（括號裡的獎勵文字可以在設定改）；一鍵複製 |
| 🗂️ 紀錄 | 以前的踏查和週會可以重新打開或刪除；**7 天後自動刪除**（清容量，可在設定改）；可下載文字備份 |
| ⚙️ 設定 | Gemini 鑰匙、模型、郵差網址和密碼、預設分享老師、發送時間、學季第一週日期（自動算年級範圍）、紀錄保留天數、名單格式 |

### 安全規則（寫在程式裡，不用每次提醒 AI）
- 照片**不存進資料庫**：只在畫面上使用，關掉就消失。縮小時也會去掉 GPS 等隱藏資訊。
- 唯一的例外：老師在「本週發送」按確認、要自動發到 IG／FB 時，照片會**暫時**放在郵差的 Google 雲端硬碟，**發完立刻刪除**（按取消也馬上刪；沒發成功的 3 天後刪）。
- 上傳照片前要先勾「每位學生都有肖像同意」。
- AI 不辨認照片中的人；文案不可以出現學生姓名、班級、座號。系統會自動掃描並標紅色提醒。
- 事實以行程表／學習單為準，AI 會列出每件事的來源讓老師核對。
- 發布前的檢查清單（肖像同意、沒有個資、內容屬實、活動結束後才發）4 項都勾了，複製按鈕才會亮。

## 第一次設定（約 20 分鐘）

### 1. 打開網站（GitHub Pages）
1. 到這個儲存庫的 **Settings（設定）→ Pages**。
2. 「Source」選 **Deploy from a branch**，Branch 選 **main**、資料夾選 **/(root)**，按 Save。
3. 等 1～2 分鐘，上面會出現網址，例如 `https://你的帳號.github.io/ieh-47714979/`。

這時候網站已經可以用了，不過是「🧪 本機試用模式」：資料只存在那台裝置的瀏覽器裡。

### 2. 設定 Firebase（正式版：換手機也看得到資料）
1. 用 Google 帳號打開 https://console.firebase.google.com ，按「建立專案」。名字隨便取，Google Analytics 可以關掉。
2. **不要升級付費方案**，用免費的 Spark 方案就好。
3. 左邊選單 **Build → Authentication → 開始使用 → Email/密碼 → 啟用 → 儲存**。
4. 左邊選單 **Build → Firestore Database → 建立資料庫**，地區選 `asia-east1（台灣）`，選「正式版模式」。
5. 在 Firestore 的 **規則（Rules）** 分頁，把內容換成這個儲存庫的 `firestore.rules` 檔案內容，按「發布」。
   > 這一步很重要，它讓每位老師只能看到自己的資料。
6. 回到專案首頁，按「</>（網頁）」圖示新增網頁應用程式，會出現一段 `firebaseConfig = { apiKey: ..., ... }`。
7. 把那幾個值貼到這個儲存庫的 `firebase-config.js` 裡（可以直接在 GitHub 網頁上按鉛筆圖示修改）。
8. **Authentication → 設定 → 授權網域**，按「新增網域」，加入 `你的帳號.github.io`。

> 💡 `firebase-config.js` 裡的 apiKey 本來就會出現在網頁裡，放在公開儲存庫是正常的。真正保護資料的是第 5 步的規則。

### 3. 設定 Gemini 鑰匙
1. 打開 https://aistudio.google.com/apikey ，按 **Create API key**。
2. 登入網站 → ⚙️ 設定 → 貼上鑰匙 → 按「檢查鑰匙」→「儲存設定」。

⚠️ **注意**：Gemini 免費版的資料，Google 可能拿去改進產品。只上傳有肖像同意的照片；鑰匙就像密碼，不要給別人，也不要寫進程式碼。

## 檔案說明

```
index.html            網頁入口
css/style.css         外觀（手機、電腦都適用，支援深色模式）
firebase-config.js    Firebase 設定（要自己貼）
firestore.rules       Firebase 資料規則（每位老師的資料分開）
js/app.js             登入、分頁切換
js/store.js           資料存放（Firebase 或本機試用模式）
js/gemini.js          呼叫 Gemini
js/prompts.js         給 AI 的指令和範例（想改語氣就改這裡）
js/utils.js           小工具：照片縮小、CSV、民國日期、個資檢查、問卷檢查
js/views/*.js         各個頁面
js/postman.js         和郵差溝通（排程、取消、查狀態）
apps-script/          📮 郵差：放到 Google Apps Script 的程式＋安裝說明（README.md）
tests/e2e.mjs         自動測試（用假的 AI 回覆、假的郵差）
tests/postman.test.mjs 郵差的測試（假的 Google、LINE、FB，不會真的發送）
```

## 自動測試

```bash
python3 -m http.server 8765
```

```bash
node tests/e2e.mjs
```

```bash
node tests/postman.test.mjs
```

（需要先安裝 Playwright。測試用的是假的 Gemini 回覆，不會花到額度。）

## 📮 自動發送（郵差）
- 老師勾完檢查清單、按「✅ 確認」後，**郵差（Google Apps Script）**在每週二 17:00 自動發到 **LINE 官方帳號**（群發）、**FB 粉專**和 **IG**。
- LINE、FB、IG 的鑰匙只放在郵差那裡，**不會出現在這個公開的程式碼裡**。
- 安裝方法：[`apps-script/README.md`](apps-script/README.md)。
- **IG** 也會自動發（一定要附照片，最多 10 張）。照片只在發送前暫存在郵差的雲端硬碟，發完就刪。
- **LINE 的照片**還是老師用手機自己傳。
